# Is it a bad time to be a technical writer?

Newer generations always get a hard time. People say the kids don't understand, they're out of control, or they're too lazy. Yet somehow the kids keep turning out alright. The Who were right!

I'm one of the newer generation of technical writers, so I'm hearing our own version of it. AI will write all the docs. Nobody reads docs any more. It's a bad time to be a technical writer.

I don't agree, though I think the pessimists are right about some things. There are far fewer junior roles, which makes it tough for new people to get into the profession. I hear of companies deciding they need fewer writers, or none at all.

What's expected of me hasn't changed much since I started tech writing in 2021. The workload has, though, for a reason that has nothing to do with AI. At the start of this year my colleague left, and I became the only writer on what had been a team of two. Team meetings got a lot shorter. My first reaction was a bit of panic, mostly about the workload. Keeping six separate MadCap Flare projects going on my own didn't look realistic, so I decided it was the right time to move all 950 or so pages to a single [docs-as-code site](https://rhysvaughan.dev/work/docs-migration/).

In the end, I got more done this year than I thought I could. That's because I could build my own tools. I use prose linting that knows our house style, checks that run every time I edit a page, and AI agents that review my changes before anyone else sees them.

None of those tools replaced the writing. I do use AI to draft some things, like release notes, but I read and edit every page myself. AI tools make mistakes. One draft assumed a new setting applied to three features, when it only applied to one. Catching that kind of thing is still on me. An LLM can tell me a sentence breaks a rule, but it can't reliably tell me whether a page answers the question a reader actually has, or whether a feature makes sense to someone who's never used it. It doesn't care what the docs mean. That's still my job, and I think it's an even more important one now.

I should say that I'm lucky. I get a lot of freedom to work the way I want, as long as the results are good, and I enjoy exploring how AI can improve our processes. Not every writer has that freedom. I also got into the profession before the number of junior roles started to fall.

If you're starting out now, the way in is harder. But a lot of what I use is free and open source, like Git, Vale, and markdownlint, while AI tools cost a monthly subscription. A docs program you've built yourself, with real checks behind it, is something to be proud of and something that shows your value.

This blog is where I'll write about what I'm learning as a technical writer while the job changes. I'll talk about the tools I'm trying, what's worked, what hasn't, and where I still want a human in the loop.

I think the docs are alright.
